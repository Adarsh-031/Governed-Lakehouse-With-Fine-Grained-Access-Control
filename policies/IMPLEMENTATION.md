# Clinical policy implementation (issue #18)

`rules.json` is the access matrix compiled for Trino **476** by
`uv run --locked python scripts/policy.py --write`. Commit the resulting rules
and `version.json` together; change `VERSION` when changing policy semantics.
`uv run --locked python scripts/policy.py` checks exact generated bytes, input
hashes and metadata, then prints the policy version and SHA-256 digest.
The compiler rejects missing/duplicate matrix cells, inconsistent table scopes,
unknown operations/visibility and changes to the five single-group logins.
The unit suite additionally checks the approved masks, types and role scopes
against the independent classification/DDL contract.

## Enforcement decisions

- Exact catalog/schema/table and authenticated user/group matches grant SELECT
  only. A final catalog denial overrides Trino's implicit `system` access;
  a final table denial catches unlisted tables and Iceberg metadata-table names.
- `schemas: []` grants no ownership; table SELECT establishes schema visibility.
  No interactive user owns tables, including admin. Identity has no grant.
- Each doctor's patients/encounters rule runs an EXISTS subquery as the reserved
  `policy_care_team_reader`. It reads care_team and only the correlated outer
  patient-token columns required by Trino's analyzer. It has no password or group
  membership and cannot be impersonated or submit interactive queries. Helper
  rules have no filters, preventing recursive evaluation.
- In 476 a privileged filter changes `current_user`. Exact doctor-login literals
  in exact user+group rules preserve caller binding. UTC query-time dates use
  half-open `[valid_from, valid_to)` intervals. NULL end is ongoing; future,
  expired, empty/reversed and missing assignments fail closed. EXISTS does not
  multiply rows when assignments overlap or duplicate.
- Matrix-hidden fields use `allow: false`, including predicates and GROUP BY;
  they are not NULL masks. Researcher ZIP and month-start masks retain VARCHAR
  and TIMESTAMP(6), including NULLs. Billing keeps exact codes and DECIMAL costs.
  Trino 476 refuses SELECT * if it references a hidden field; use an explicit
  permitted projection. SHOW/information_schema omit hidden columns.
- Iceberg's `$path`, `$partition`, and `$file_modified_time` columns are explicitly
  denied to prevent storage-path/partition disclosure outside the inventory.
- Empty impersonation, authorization, system information, session property,
  function and procedure sections close omitted-section defaults. Trino always
  permits `system.builtin` functions; empty function rules deny connector/table
  functions. Query rules grant execution only, preventing cross-user query
  viewing/killing (users retain management of their own queries).
- Trino's file controller does not check `ALTER TABLE ... EXECUTE` privileges.
  A second built-in **read-only** system controller denies table procedures and
  mutations. Both controllers must approve access. Keep both files in
  `access-control.config-files`; CI verifies configuration and actual denial.

## Deployment and evidence

After reviewing generation, check the policy and recreate Trino to apply the new
read-only bind mount (a restart alone does not add mounts):

```sh
uv run --locked python scripts/policy.py --experiment-dir results/raw/run-001/policy
export TRINO_UID="$(id -u)" TRINO_GID="$(id -g)"
docker compose --env-file data/secrets/runtime.env up -d --wait --force-recreate --no-deps trino
```

The experiment directory freezes the exact rules, policy manifest, group map,
contracts and controller settings. Identical reruns preserve them; a different
policy in the same run directory fails. Record this manifest with each access
or performance experiment and its results; a digest without the retained policy
is insufficient to reproduce an experiment. Later policy-only edits require a
Trino restart; no live refresh is configured. Do not change files during a run.
The new Docker acceptance test records the manifest and verifies its rules bytes
match the policy mounted for all assertions.

```sh
uv run --locked --group dev pytest tests/unit -q
RUN_POLICY_INTEGRATION=1 uv run --locked --group dev pytest tests/integration/test_policy.py -v
```

Runtime checks exercise every CSV decision, returned types and mask outputs,
both source-derived doctor sets, UTC date boundaries, overlap/duplicates, joins,
CTEs, historical snapshots, star expansion, SHOW/information_schema metadata,
and denied operations. CI also retains HTTPS/authentication and DDL regressions.

## Boundaries

Audit admin metadata SELECT is implemented and tested using an isolated fixture
catalog alias. Production still has no audit catalog/read warehouse or S3 read
grant; its delivery pipeline remains later work. Restricted query text stays
hidden even from admin. The production identity path remains ETL-only.

Trino 476 automatically allows information_schema in an accessible catalog;
metadata is then filtered by table/column access. File column rules are a deny
list, not a future-column whitelist: trusted schema changes must pass the
inventory/matrix/DDL checks and review before loading. These controls do not
protect against a trusted host/ETL operator intentionally bypassing that process.
HMAC and generalization do not establish anonymity. Issue #5 teammate sign-off
remains pending; implementation does not invent that approval.
