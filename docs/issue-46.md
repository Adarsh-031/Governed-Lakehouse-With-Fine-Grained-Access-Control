# Issue #46 — mitigating researcher aggregate inference and linkage

**Finding (#23/#24):** the researcher role read patient-level rows with age band,
sex, masked ZIP and visible reason codes. That allowed singleton equivalence
classes, exact count differencing (total minus "everyone except X") and exact
auxiliary-data linkage to a released pseudonymous token.

## Decision: aggregate-only research releases

The researcher privacy contract is now:

| Data | Before #46 | After #46 |
|---|---|---|
| `silver.patients` | token, age band, sex, race, ethnicity, ZIP prefix | **token only** (all quasi-identifiers hidden) |
| `silver.encounters` | token, class, code, reason code, month-masked times | token, class, code, month-masked times (**reason code hidden**) |
| Demographics | row level | `hospital.gold.researcher_demographics` (age band × sex × race) |
| Geography | row level ZIP prefix | `hospital.gold.researcher_geography` (3-digit prefix) |
| Conditions | row level reason code | `hospital.gold.researcher_conditions` (reason code) |

Every gold cell counts **distinct patients**, and any cell with fewer than
**11** patients is suppressed (dropped, not shown as 0 or "<11"), the common
health-statistics small-cell rule. Release tables contain no patient token or
record key. Doctors and billing are denied; admin can read them.

Why this blocks the measured attacks:

- **Linkage:** research rows carry only the pseudonymous token, so an attacker's
  auxiliary age band, sex, ZIP and rare-condition signature match nothing. A gold
  cell can at best narrow a person to 1 of ≥ 11 patients.
- **Differencing:** gold has no record-level predicate. Removing one person from a
  cell of 11 makes the cell disappear instead of revealing a count of 1, and SQL
  predicates on hidden silver columns are denied.
- **Rare conditions:** reason codes shared by fewer than 11 patients are never
  published.

## Implementation

- `policies/schema-contract.yaml`, `policies/access-matrix.csv`, `ingest/pii_tags.yaml`:
  three gold tables with four explicit decisions each; researcher silver
  quasi-identifiers and `reason_code` changed to hidden. `rules.json` and
  `version.json` regenerated by `scripts/policy.py --write`.
- `ingest/release.py`: pure `build()` (distinct-patient cells, threshold) and
  `publish()` (reads silver with the trusted ETL catalog, replaces each gold table,
  verifies readback). `ingest.pipeline` publishes after every load; the test
  fixture republishes after appending its boundary patients.
- `sql/schema/60_gold.sql`: DDL for the three releases.
- `sql/queries/researcher.sql`: R1 and R4 now read gold.
- Tests: `tests/unit/test_release.py` (suppression, distinct counting,
  differencing, NULL keys); policy/access/schema integration tests cover gold
  grants, suppression of the boundary cohort and denial of hidden silver columns;
  the `aggregate_inference` and `quasi_identifier_linkage` bypass cases now record
  before/after metrics on the same population and fail if any published cell is
  below 11 or any unique correct link remains.

## Residual risk (accepted, documented)

- Complementary differencing across the three releases and over time is limited
  (no shared totals or record keys) but not formally bounded. A privacy budget or
  differential privacy would be needed for a guarantee.
- Encounter `code` and month-level timestamps remain row-level for utilization
  research and could support attribute inference by an attacker who already knows
  a token's encounter history.
- Synthetic population only; these measurements are not real-world
  re-identification probabilities, and k ≥ 11 is not an anonymity proof.
- The committed benchmark run (results/raw/bench-20261030T174823Z) measured the
  pre-#46 researcher queries.
